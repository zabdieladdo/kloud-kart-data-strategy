# Kloud Kart: 12-Month Roadmap

**Prepared for:** Nana Adjei, Head of Operations
**Consultant:** Zabdiel Yidjiemo Addo

**Starts:** month 1 = the month the plan is approved. 
Assumes both hires start at the beginning of month 2 (A29) and 90 days remain on the complaint (A13).

| Quarter | Outcome Nana can check herself | How she checks it | Root cause it closes |
|---|---|---|---|
| **Q1 (months 1–3): stop the damage, answer the complaint** | End of month 1: Nana's Monday report no longer slows the shop. A temporary measure (the export runs overnight) holds until the copy is ready. | A one-line sheet shows the shop's response time during the report hour against the range agreed for a normal Monday hour | RC1 |
| | End of month 1: Kloud Kart's registration with the Data Protection Commission is confirmed current | The certificate, with its expiry date | RC4 |
| | By day 60: Nana holds a list of every place customer data is kept, each with an owner. The complaining customer is shown as removed from each, and the response has gone to the Commission. | She opens the list and the deletion record; a copy of the sent response | RC4 |
| | End of month 2: a one-page definition of a sale, signed by Nana and Finance. If it isn't signed, the dispute is on the board's agenda. | The signed page, or the agenda item | RC2 |
| | End of month 3: the report reads only from the separate copy, and every page shows "as of" a time | The "as of" line on the report | RC1 |
| | From month 1: each week, a count of orders cancelled because the item wasn't in stock | A weekly number she receives | Overselling (risk; sets the starting point) |
| **Q2 (months 4–6): one number** | Nana and Finance show the same sales total for every week since the definition was signed, for 4 weeks in a row, including one month-end close | She compares two figures on one page | RC2 |
| | The Monday report is waiting for her by 08:00 every Monday, and she spends no time rebuilding it | It's in her inbox; she notes her Monday time | RC3 |
| | Orders cancelled for lack of stock fall from the Q1 count to 1 or fewer a week for those caused by a wrong system count, and half the Q1 count for the rest | The same weekly number | Overselling (risk) |
| | Nana can see how many days each item was out of stock last month | One table in the report | Overselling (risk), and the history a future forecast needs |
| **Q3 (months 7–9): trust it without asking** | When a figure is wrong or missing, Nana gets a message the same morning, before she reads the report | The message, and a log she can open | RC3, RC2 |
| | Any one customer can be found in every copy within one working day (falling to one hour by Q4), tested monthly | The monthly test result on one line | RC4 |
| | Nana answers three Monday questions she couldn't before (for example: days out of stock, Ghana against Nigeria, refunds by category) | She answers them from the report | RC2, RC3 |
| **Q4 (months 10–12): hand-over and review** | Nana and Finance answer their common questions from the report without asking the hires, and the number of requests to the hires falls | A count of requests by month | RC2 |
| | The board receives the year's figures from one source, plus a decision on each item put on hold: forecasting, hourly refresh, a third hire | The board pack | Not applicable |

**If a hire starts late:** work on customer data and the complaint (RC4) is protected; the developer keeps the copy running and the Operations owner runs the register. Q2 outcomes slip by the length of the delay.

**If fewer than about 35 days remain on the complaint:** the privacy work takes the developer's time ahead of the copy, and the overnight export stays as the stopgap for longer.
